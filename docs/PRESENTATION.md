## 1. 프로젝트 주제

**Cammand (Camera + Command)**  
카메라 손 제스처로 가정 내 IoT 기기를 제어하는 온디바이스 스마트홈 허브

- 라즈베리파이5 + Hailo-8L NPU 기반 엣지 AI 제스처 인식
- Home Assistant(HA)와 MQTT로 연동해 조명, 선풍기, 에어컨, 가습기 제어
- 말하지 않고, 기기를 만지지 않고, 손 모양과 움직임만으로 조작

## 2. 프로젝트 목표와 필요성

### 2-1. 문제 인식: 음성 기반 스마트홈 제어의 한계

AI 스피커는 스마트홈 제어의 대표 인터페이스지만, 실사용 환경에서 인식 실패가 반복적으로 보고됨.

| 조사 | 대상 | 주요 수치 |
|------|------|-----------|
| 한국소비자원 (2017) [1] | AI 스피커 이용자 300명 | 일상 환경 음성인식 미흡 **56.7%**, 외부 소음을 명령으로 오인식 **37.0%** |
| 컨슈머인사이트 (2018) [2] | 전국 14~64세 12,580명 | 이용 만족률 **49%**, 불만 사유: 음성 명령 인식 불량 **50%**, 소음 오인식 **36%** |
| JMIR 연구 (2020) [3] | 운동·언어·인지 장애 사용자 16명 | 음성 비서 인식 정확도 **58.5%** (일반 음성 기준 만족 수준 90~95%) |

**음성 인터페이스가 불리한 사용자와 환경**

| 구분 | 상황 | 근거 |
|------|------|------|
| 발화 제약 사용자 | 언어장애, 청각장애로 발음이 불명확한 경우 | 2025년 등록 청각장애인 **449,269명** (전체 등록장애인의 17.1%) [4] |
| 소음 환경 | TV, 주방, 가전 소음 속 명령 인식 실패 | 소음 오인식 36~37% [1][2] |
| 소음 민감 환경 | 영유아 수면 중, 심야, 공유 주거 공간 | 소리 내어 명령하기 어려운 상황 |

### 2-2. 해결 방안: 제스처 기반 스마트홈 제어

| 항목 | 내용 |
|------|------|
| 입력 방식 | 음성 대신 손 제스처 (손가락 수, 원 그리기, 좌우 흔들기, 손바닥 상하 이동) |
| 처리 위치 | 기기 내부(엣지)에서 처리, 영상이 외부 서버로 나가지 않음 |
| 가속 | Hailo-8L NPU (13 TOPS) [5] |
| 연동 | Home Assistant + MQTT |

### 2-3. Home Assistant 연동의 이점

| 지표 | 수치 | 출처 |
|------|------|------|
| 설치 가구 수 | **200만 가구 이상** | GitHub Blog (2025.12) [6] |
| 지원 브랜드 | **3,000개 이상** | GitHub Blog (2025.12) [6] |
| 분석 동의 활성 설치 수 | **690,936대** (동의율 25% 미만 기준) | HA Analytics [7] |
| GitHub 기여자 수 | 2024년 **21,000명 이상**, 전체 공개 프로젝트 중 **1위** | GitHub Octoverse 2024 [8] |
| 성장세 | 2025년 기여자 수 기준 가장 빠르게 성장한 오픈소스 프로젝트 중 하나 | GitHub Octoverse 2025 [6] |

- 오픈소스 스마트홈 플랫폼 중 최대 규모의 사용자·개발자 생태계
- Cammand는 MQTT 토픽(`cammand/power/<기기>`, `cammand/knob/<기기>`)만 발행하고, 실제 기기 제어는 HA 자동화가 담당
- HA가 지원하는 기기라면 Cammand 코드 수정 없이 HA 자동화 추가만으로 제어 대상 확장 가능
- MQTT Auto-Discovery로 HA 대시보드에 인식 결과·피드백 센서 자동 등록

## 4. 프로젝트 수행 내용

### 4-1. 시스템 구성

```
카메라 (imx708, 640x360)
   │
   ▼
MediaPipe 손 랜드마크 추출 (CPU, 21개 관절 x xyz)
   │
   ▼
제스처 분류 (Hailo-8L NPU)
   │   정적 모델: 손가락 수 등 7클래스  (1, 63) → (1, 7)
   │   동적 모델: 궤적 4클래스         (1, 630) → (1, 4)
   ▼
상태 머신 (선택 → 조작 → 해제)
   │
   ▼
MQTT 발행 → Home Assistant 자동화 → IoT 기기
```

### 4-2. 제스처 체계

| 단계 | 제스처 | 동작 |
|------|--------|------|
| 기기 선택 (2초 유지) | 손가락 1~5개 (보조 제스처: 엄지척, 총모양, 엄지+검지+중지) | 방 조명 / 스탠드 조명 / 선풍기 / 에어컨 / 가습기 |
| 전원 제어 | 검지 유지 후 원 그리기 / 좌우 흔들기 | ON / OFF |
| 값 조절 | 손바닥 수평 유지 후 상하 이동 | 밝기, 풍량, 온도, 습도 조절 |
| 해제 | 주먹 1.5초 유지 | 기기 선택 해제 |

### 4-3. 기존 기술과의 차별성

| 비교 항목 | AI 스피커 (음성) | 스마트폰 앱 | **Cammand (제스처)** |
|-----------|------------------|-------------|----------------------|
| 입력 방식 | 발화 | 화면 터치 | 손 제스처 |
| 소음 영향 | 큼 (오인식 36~37%) | 없음 | 없음 |
| 발화 제약 사용자 | 사용 어려움 | 사용 가능 | 사용 가능 |
| 조작 준비 | 호출어 + 명령 | 기기 꺼내기, 앱 실행 | 카메라 앞에서 즉시 |
| 처리 위치 | 주로 클라우드 | 클라우드 / 로컬 | 기기 내부 (엣지 NPU) |
| 개인정보 | 음성이 서버로 전송 | — | 영상이 외부로 나가지 않음 |
| 연속 값 조절 | 단계별 명령 반복 | 슬라이더 | 손 높이로 연속 조절 |

**핵심 차별점**

1. **온디바이스 처리**: 영상 분석을 라즈베리파이5 + Hailo-8L 내부에서 수행, 네트워크 지연·개인정보 유출 위험 없음
2. **경량 입력 설계**: 이미지 대신 21개 관절 좌표(63차원)를 모델 입력으로 사용해 연산량 최소화
3. **오작동 방지 상태 머신**: 선택 2초 유지, ON/OFF 진입 0.5초, 값 조절 진입 0.4초, 해제 1.5초 등 유지 시간 기반 확정
4. **보조 제스처**: 같은 기기를 두 가지 손 모양으로 선택 가능해 손 모양이 불편한 사용자도 조작 가능
5. **HA 표준 연동**: MQTT 토픽 규약만 따르면 기기 추가 가능, HA 대시보드에 실시간 피드백 표시

### 4-4. 실측 성능 (2026-09-29, 라이브 카메라 프레임)

| 엔진 | 평균 | p50 | p95 |
|------|------|-----|-----|
| MediaPipe (CPU) | 41.8 ms | 39.4 ms | 57.1 ms |
| MediaPipe + Hailo NPU | 49.6 ms | 46.9 ms | 69.9 ms |

- 처리 주기 10Hz(100 ms) 안에서 동작
- 카메라 캡처 25.7 fps

## 7. 기대효과 및 발전 방향

### 7-1. 기대효과

| 구분 | 효과 |
|------|------|
| 접근성 | 언어·청각장애 등 발화가 어려운 사용자도 스마트홈 제어 가능 |
| 사용 환경 | 소음 환경, 소음 민감 환경(수면, 심야)에서도 조작 가능 |
| 개인정보 | 음성·영상을 외부로 보내지 않는 로컬 처리 |
| 확장성 | HA 생태계(3,000개 이상 브랜드)와 연동해 기기 추가 용이 |
| 비용 | 라즈베리파이5 + AI Kit 기반 저비용 구성 |

### 7-2. 발전 방향

| 방향 | 내용 |
|------|------|
| 음성 인식 병행 | 제스처와 음성을 함께 지원하는 멀티모달 입력, 상황에 따라 편한 방식 선택 |
| 두 손 제스처 인식 | 한 손은 기기 선택, 다른 손은 조작 등 동시 입력으로 제스처 표현력 확대 |
| 제어 기기 확대 | 커튼, 도어락, TV, 로봇청소기 등 HA 연동 기기로 대상 확대 |
| 인식 정확도 향상 | 데이터 추가 수집·증강, 모델 구조 개선, 사용자별 보정 |
